# Даты батчей

`marketplace_elt` использует `dag_run.logical_date` как `_extracted_at` всего
батча. В staging это `load_dts`, а в DDS — точки истории `valid_from`.
`valid_to` равен началу следующей версии; у текущей версии — `infinity`.
Дата покупки заказа остаётся бизнес-датой и не определяет историю атрибутов.

Для ручного запуска задайте logical date через UI Airflow или CLI:

```bash
docker compose exec -T airflow airflow dags trigger marketplace_elt \
  --logical-date '2026-11-02T16:00:00+03:00'
```

Выбирайте дату по фактическому снимку источника и позже предыдущих батчей.
Без explicit logical date ручной запуск использует фиксированный `run_after`
из DagRun, а не часы выполнения задачи. Повторы используют ту же дату в UTC.
Команда `python -m pipelines.source_to_raw` вне Airflow сохраняет прежнее
поведение: дата создаётся при открытии ручного батча.

До загрузки `open_batch` проверяет историю строк и снимков ключей в raw.
Дата раньше существующей или совпадающая с датой другого батча отклоняется:
инкрементальные ODS-модели обрабатывают только `load_dts > watermark`.
Повтор того же батча с той же датой допускается, пока нет более поздних батчей.
Одновременный запуск DAG и ручного EL вне Airflow не поддерживается.

Имеющиеся даты не переписываются. Новая дата запуска не создаёт версию без
изменения атрибутов. Исторический replay требует соответствующих снимков
источника и отдельной пересборки; текущий снимок не восстанавливает прошлое.

Проверка выбора даты и порядка батчей в отдельной временной БД:

```bash
docker compose exec -T airflow python /opt/project/scripts/check_batch_time.py
```
