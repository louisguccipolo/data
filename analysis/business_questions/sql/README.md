# Метрики в PostgreSQL DWH

Сборка: `docker compose exec airflow bash -c 'cd /opt/project/dbt && dbt build'`.
SQL 01–05 выполняются в SQL Lab Superset (Marketplace DWH) или psql базы dwh.

Выручка в BRL — price доставленных позиций без freight. Средний чек включает
freight: сначала сумма по заказу, затем среднее по доставленным заказам.
Повторные покупатели определяются по customer_hk (хеш customer_unique_id),
учитываются все статусы. Одна позиция = одна единица товара.
Месячная витрина содержит 24 месяца [2016-09, 2018-09), включая нулевые.
Остальные витрины охватывают всю выгрузку. Пустая категория: __unknown__.
Orders_count по продавцам и категориям, средние и проценты нельзя складывать.
Платежи и отзывы не присоединяются к позициям, чтобы не размножать выручку.

DDS этой реализации — текущий снимок из типизированного staging ODS,
с выбором последней версии по load_dts и batch_id. Это не SCD2 и не реконструкция
истории Data Vault: удаление сущностей по eff_* пока не применяется.
История в ODS сохраняется, но метрики отражают последнюю известную версию.
Факты: одна строка на заказ / позицию; измерения — на товар, продавца и профиль.
Полная пересборка таблиц обновляет витрины при каждом dbt build.

mart_reconciliation проверяет зерно и сходимость сумм на любых данных.
Контрольные значения исходного Olist: 13 221 498,11 BRL; 96 478 доставленных
заказов; чек 159,88; 96 096 покупателей, из них 2 997 повторных; 74 категории.
